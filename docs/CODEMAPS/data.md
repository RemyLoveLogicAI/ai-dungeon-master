# Codemap: data

## SQLite — `data/campaigns.db`

Written by `campaign_core.CampaignStore` — instantiated by
`engine/api_server.py` and `game_server.py`; `campaign_service.py` receives a
store instance and opens none itself; `campaign_mcp.py` never touches the
store (stdio adapter → HTTP → `game_server`). Path overridable only for
`game_server` via `AI_DM_CAMPAIGN_DB`; the API server hardcodes
`<repo>/data/campaigns.db`.

Schema (`campaign_core.py:105-116`):

```sql
CREATE TABLE campaigns (
    id TEXT PRIMARY KEY,
    revision INTEGER NOT NULL,
    state TEXT NOT NULL            -- JSON document
);
CREATE TABLE requests (
    campaign_id TEXT NOT NULL REFERENCES campaigns(id),
    request_id TEXT NOT NULL,
    action TEXT NOT NULL,
    response TEXT NOT NULL,        -- JSON replay snapshot
    PRIMARY KEY (campaign_id, request_id)
);
```

- `PRAGMA journal_mode=WAL`, `foreign_keys=ON`, `BEGIN IMMEDIATE` transactions.
- `commit()` bumps `revision` and inserts the request row atomically; replayed
  `request_id` returns the stored response (`ConflictError` on action
  mismatch).
- `update_media()` merges `state.media[kind]` without a revision bump.
- File created mode `0600`, parent `0700` — applied only on the create path;
  pre-existing files keep their permissions. State JSON capped at 2 MB
  (`_MAX_STATE_BYTES`). Campaign ids must be canonical UUIDs
  (`uuid.UUID` round-trip check) and request ids must match the `_TOKEN`
  regex — validated in `campaign_core`.
- Campaign `state` shape (campaign_service): `{id, revision, title, phase,
  stage, scene, game, journal, character, media, presentation}`; the
  api_server/`character_service` path passes `{title, phase, character}` and
  `CampaignStore.create` adds `id` (fresh UUID) and `revision: 0` on top.

## Combat log envelope — `combat-encounter-log/1`

- Schema artifact: `schemas/combat-encounter-log-1.schema.json` (published;
  wheel includes it). `combat_schema.validate_payload` applies it; needs the
  optional `schema` extra (`jsonschema`), else `SchemaUnavailableError`.
- Writers: `combat_log.save_log` (atomic temp-sibling + replace, file fsync
  before replace, POSIX parent-dir fsync best-effort — only `EINVAL`/
  `ENOTSUP` suppressed), `combat_runner`, `tui_runner` (`--log`,
  `--resume`, `--validate-schema`).
- Readers: `combat_log.load_log` (strict, bounded: `MAX_LOG_BYTES` 4 MiB,
  `MAX_LOG_ENTRIES` 100k), `verify_log` (every entry must replay).
  `tui_runner.read_resumed_state` consumes saved state on `--resume` (lives
  in `tui_runner.py`, not `combat_log.py`).
- Default directory (`default_log_dir()`, used by the TUI `--resume`
  fallback): `AI_DM_LOG_DIR` or `$XDG_CACHE_HOME/ai-dungeon-master/logs`
  / `~/.cache/ai-dungeon-master/logs`. Explicit `save_log`/`load_log` paths
  resolve relative to the caller's cwd, not this directory.

## Generated artifacts

- `web/demo-data.json` (37.8 KB): generated by `web/build_demo.py` from the
  real engine modules; `pages.yml` fails on drift. Committed, not runtime data.
- `audio_output/`: generated WAV SFX (`dice_roll`, `sword_clash`,
  `fireball_impact`, `crit_fanfare`, `ambient_drone`, `cavern_ambience`,
  `tension_pulse`). Per entry point: `engine/api_server.py` generates once
  at import into `<repo>/audio_output`; standalone `tui_runner` and
  `vr_server.py` generate into `default_audio_dir()` (`AI_DM_AUDIO_DIR` or
  the XDG cache); `combat_runner` writes `<cwd>/audio_output` unless its
  `audio_dir` parameter is passed; `engine/dm_tui.py` generates none.
  Gitignored runtime output.
- `test_driver_receipt.json`: output of `python test_driver.py`, written to
  the hardcoded path `/private/tmp/ai-dm-feat-pr/test_driver_receipt.json`;
  the parent directory must exist or the run fails at the receipt write.

## What has no DB

- `client/` (React): all state in memory + `localStorage.adm_campaign_id`;
  no persistence of its own.
- `web/` static demo: reads `demo-data.json` only.
- `vr_server.py`: in-memory `CampaignVRState` per process; no disk writes
  besides SFX generation.
- `game_foundation` sessions: in-memory, append-only event log.
